# AgentRAG EvalKit 分阶段执行任务清单

> 文档用途：用于实际开发执行、验收和进度记录。
>
> 状态约定：`[ ]` 未开始，`[~]` 进行中，`[x]` 已完成，`[!]` 阻塞，`[-]` 取消或移出当前范围。
>
> 执行原则：先完成真实 Agent/RAG 的最小评测闭环，再逐步增加 Web UI、持久化、异步任务和企业级能力。每个阶段必须通过验收门槛后才能进入下一阶段。

## 4. S1：打通真实 HTTP Agent/RAG 最小闭环

### 阶段目标

在不引入数据库、Redis 和复杂前端的情况下，让 EvalKit 能够通过配置的 HTTP 地址调用真实 Agent/RAG，并完成一批评测。

### 执行任务

- [x] S1-01 定义 AdapterConfig、AdapterType 和 AdapterVersion 最小模型
- [x] S1-02 实现 AdapterRegistry，根据 `adapter_id` 解析已注册 Adapter
- [x] S1-03 删除主执行 API 中固定使用 `MockRagAdapter` 的逻辑
- [x] S1-04 扩展创建 EvalRun 请求，保存 Adapter ID、版本、非敏感配置快照和模型标识
- [x] S1-05 增加 `POST /api/v1/adapters/test` 连接测试接口
- [x] S1-06 校验 HTTP/HTTPS 地址、超时、鉴权头和响应结构
- [x] S1-07 对答案、引用、召回或 Trace 字段缺失的响应标记为 `not_evaluable`
- [ ] S1-08 增加网络失败、HTTP 错误、超时和契约错误分类
- [ ] S1-09 支持通过环境变量传入 Bearer Token，禁止在接口响应中回显
- [ ] S1-10 改造 `scripts/demo_http_eval.py`，允许选择数据集和目标地址
- [ ] S1-11 使用本地 Mock RAG 完成主 API 真实 HTTP 调用测试
- [ ] S1-12 使用 Reference RAG 完成 BM25 与 Hybrid 对比测试
- [ ] S1-13 编写 Adapter 注册、连接测试和错误场景单元测试

### 验收门槛

- [ ] 用户可以指定一个 HTTP Agent/RAG 地址并测试连接
- [ ] EvalRun 执行时使用选定 Adapter，而不是固定 Mock
- [ ] 至少 4 条样本可通过真实 HTTP 请求完成评测
- [ ] 结果包含答案、引用、召回 Chunk、Recall@K、MRR 和错误信息
- [ ] 契约字段缺失时不会误判为成功或零分
- [ ] 原有 55 项测试及新增测试全部通过

1. 启动 Mock RAG 或 Reference RAG。
2. 调用 Adapter 连接测试接口。
3. 导入或加载示例数据集。
4. 创建绑定 HTTP Adapter 的 EvalRun。
5. 执行评测并查询逐 Case 结果。
6. 导出 CSV，确认结果来自真实 HTTP 调用。

## 15. 注意事项

- 本文使用未勾选任务表示真实开发状态；完成代码、测试和验收后才能改为 `[x]`。
- 每次只推进一个阶段的主链路，不要同时展开数据库、前端、权限和多框架接入。
- S1 和 S2 优先保持轻量本地运行，避免过早引入大型 Docker 环境。
- 每个阶段结束时必须保存测试证据、提交编号和遗留问题。

- 需求引用以总任务文档 `tasks.md` 和原始需求文档为准，执行清单用于排序与记录，不替代需求定义。
- 属性测试验证状态机、幂等性、快照不可变和权限隔离等长期不变量；单元测试验证组件，集成测试验证服务协作，端到端测试验证用户完整流程。
